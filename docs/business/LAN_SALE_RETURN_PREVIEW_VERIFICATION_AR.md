# المحطة الثانية — حماية معاينة مرتجع تسوية المبيعات الشبكي

## التنفيذ

- يقرأ النموذج الشبكي تفعيل الضريبة والمعدل الافتراضي والشمول من كتالوج الخادم، ويقرأ قواعد الأصناف ويعيد الحساب بالمحرك المشترك. لا يعتمد إعدادات الضريبة المحلية لجهاز العميل.
- يرسل الطلب `expectedPricingFingerprint` لبصمة مبالغ الفاتورة والبنود والخصومات ومعدلات الضريبة والشمول. يقارن الخادم نتيجة حسابه بالبصمة داخل نفس معاملة إنشاء وترحيل المرتجع.
- يقرأ الخادم سياسة SQL الدائمة عند الترحيل وعرض الكتالوج؛ لا يظل تحديث المعاينة محصورًا في ذاكرة إعدادات متقادمة. السياسة الدائمة المطلوبة والمفقودة ترفض العملية.
- الاختلاف يرجع409 مع `pricing_preview_changed` دون كتابة مالية. يحتفظ النموذج بالبنود والخصومات ويحدث المعاينة، ثم يعرض رسالة المراجعة الموجودة باللغات الثلاث دون اعتماد تلقائي. فشل تحديث المعاينة يبقي البيانات ويعرض رسالة فشل التحديث.
- تُحفظ التعديلات المتزامنة على البنود أثناء إعادة قراءة الكتالوج بإعادة المحاولة عند تغير القائمة.
- الطلب المترحل سابقًا يرجع نتيجته قبل مقارنة البصمة. هذا لا يعالج بعد حفظ هوية محاولة العميل عبر انقطاع اتصال غير محسوم وإعادة تشغيل التطبيق.

## الاختبارات والحدود

أُضيفت5 حالات من النموذج إلى الخادم عبر JSON: سعر شامل وغير شامل، تعطيل، إعفاء، ومعدل صنف. يتحقق الاختبار من معاينة الضريبة والخصم، وتغير سياسة SQL دون تحديث ذاكرة الإعدادات، ورفض الطلب الأول بلا تغيير في المستندات أو المخزون أو القيود، وتحديث المعاينة، واعتماد ثانٍ صريح، وإعادة الطلب دون تكرار واتزان القيود.

الحقل اختياري للتوافق مع العملاء السابقين، والخوادم القديمة قد تتجاهله؛ ضمان المطابقة يتطلب تحديث الطرفين. البصمة مقارنة محاسبية وليست تفويضًا أو توقيعًا أمنيًا. تفعيل المخازن الإضافية والعملات المتعددة لم يحدث بهذه الخطوة.

نجحت162 حالة في تشغيل مجمع للشبكة والمرتجعات المحلية وتهيئة المخازن وتسويات وتقييم FIFO. التحليل بلا ملاحظات. السجلات `/tmp/tapix-sale-lan-fifo-final-tests.log` و`/tmp/tapix-sale-lan-fifo-analyze-final.log`.
