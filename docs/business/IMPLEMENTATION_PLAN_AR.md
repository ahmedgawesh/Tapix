# خطة تنفيذ الفروع والمخازن — 19 سبتمبر 2026

## القرارات المعتمدة

- البرنامج الحالي يظل قابلًا للبيع والعمل لفرع واحد دون شراء إضافة أو إعداد شبكة.
- الأساس شركة واحدة، والجهاز الرئيسي لكل فرع مسؤول عن كتاباته المحلية؛ انقطاع الإنترنت أو المركز لا يوقف الفرع.
- استقلال كل كاشير عن الجهاز الرئيسي، وتوحيد شركات قانونية مختلفة، خارج أول إصدار للفروع.
- إضافة الفروع/المخازن لها استحقاقات مدفوعة مستقلة عن Pro والترخيص الحالي. لا يُستخدم `isPro` لمنحها تلقائيًا، ولا تنقل ميزة حالية من الباقة الحالية إلى الإضافة.
- واجهة وبيانات مشتركة للمنصات؛ خدمات الشبكة والخلفية تُنفذ حسب قدرة المنصة. Web ليس خادم LAN؛ تشغيله دون إنترنت يحتاج أصلًا تحميل التطبيق والبيانات وقيود تخزين المتصفح.

## خارطة الطريق المتبقية

حُددت في 21 سبتمبر 2026 أربع مراحل رئيسية غير مكتملة، موزعة على ثماني محطات تنفيذ لها شروط إغلاق واضحة. المرجع التنفيذي للمتابعة: [خارطة الطريق المتبقية](REMAINING_ROADMAP_AR.md). تبدأ المحطة التالية بإغلاق حصر مسارات المخزون المتبقية، مع إبقاء ترقيم المراحل الأصلية أدناه.

## ترتيب التسليم وبوابات التفعيل

1. أساس البيانات والتوافق: شركة/فرع/مخزن رئيسي، هوية قاعدة دائمة، ترقية إضافية مع مطابقة البيانات القديمة، API قراءة للمخزن الافتراضي. هذه الخطوة لا تفعّل تشغيل مخازن متعددة.
2. محرك مواقع المخزون: هوية المستند وموقعه، الكميات والدفعات والتكلفة لكل مخزن، حركات ذرية وصرف/استلام جزئي وتحويلات بالطريق؛ تحديث جميع مسارات البيع والشراء والمرتجعات والجرد والتقارير والصلاحيات.
3. التشغيل المحلي متعدد الفروع: خدمة مستقلة عن الواجهة، صلاحيات الموقع داخل الخادم، إدارة الأجهزة، وتراخيص منفصلة موقعة وحدود الفروع/الأجهزة.
4. المزامنة: outbox في معاملة الترحيل، inbox ومنع التكرار، ترتيب أحداث الفرع، سجل عمليات غير قابل للاستبدال، ملكية كتابة محددة، واختبارات انقطاع وتكرار واستعادة نسخة احتياطية. هوية القاعدة ليست هوية جهاز؛ استنساخ قاعدة نشطة لا يسمح بكاتبين بنفس الهوية.
5. المركز: API مستقل وPostgreSQL واستضافة محلية/سحابية، تقارير المزامنة والإغلاق المركزي والاشتراكات والتجربة المحدودة.

## قيود سلامة الإصدار التأسيسي

- مخطط 10083 إضافي؛ لا يعيد حساب مخزون أو تكلفة أو رصيد ولا يغير أرقام فواتير أو معرفات قديمة.
- في 10083 كان المخزن الرئيسي يقرأ رصيد المتغير مباشرة. في 10086 أصبح له رصيد حسب المخزن، مع توافق ذري بينه وبين حقول المتغير الحالية أثناء نقل مسارات التشغيل تدريجيًا. لا تُفعّل مخازن إضافية قبل اكتمال الدفعات والتقارير والتحويلات.
- لا توجد واجهة لتبديل الفرع/المخزن الحالي؛ تغيير السياق قبل إسناد المستندات إلى مواقعها قد يعيد نسبة التاريخ لفرع آخر.
- لا مزامنة لقواعد حالية مستقلة بمجرد تطابق أسماء الأصناف أو العملاء. يلزم ضم مؤسسة ومطابقة هويات صريحة في مرحلة المزامنة.
- لا تغيير على تفعيل الاشتراكات الحالية أو مفاتيح توقيعها أو أسعارها في هذه المرحلة.
- يجب الحفاظ على الأصناف بمتغيرات وبدون متغيرات، والمرتجعات المرتبطة بالفواتير ومرتجعات التسوية المستقلة، وخصم كل بند وخصم الفاتورة واجتماعهما. أي تغيير لمسار مخزن يُختبر على هذه الحالات؛ لا يعيد تسعير المرتجع المرتبط بالأسعار الحالية ولا يحوّل تسوية مستقلة إلى مرتجع يشترط فاتورة.
- التفعيل التجاري والتشغيلي للفروع يحتاج اكتمال اختبارات كل المسارات. وجود جدول branches لا يعني جاهزية تشغيل فروع.

## تحقق الترقية المطلوب

- قاعدة جديدة وقاعدة 10082 بها بيانات، ثبات الهوية بعد إعادة الفتح والاستعادة، استقلال الهوية بين قواعد مختلفة.
- مطابقة حسابات/قيود/عملاء/موردين/فواتير/دفعات مخزون ومبالغ وقياسات قبل الترقية وبعدها.
- فشل الترحيل في منتصف إضافة الجداول لا يترك نصف هوية أو مخططًا نصف مكتمل.
- منع ربط مخزن بفرع من شركة أخرى، ومنع حذف الفرع/المخزن المشار إليهما في السياق.
- استمرار الاختبارات الحالية للبيع والشراء والمرتجعات والجرد والتكلفة والترخيص.
- تحليل الكود والاختبارات المناسبة في كل دفعة، وبناء Android وLinux عند نهاية كل محطة فقط طبقًا لتحديث المستخدم بتاريخ21 سبتمبر2026. بناء Web مؤجل إلى المرحلة الأخيرة بطلب المستخدم بتاريخ 20 سبتمبر 2026 لتوفير الوقت؛ Windows وApple يحتاجان بيئتي البناء والأجهزة المناسبتين.

## نشر العملاء

تغييرات التطوير ليست تصريح نشر تلقائي. يُختبر الإصدار على نسخة من قاعدة حقيقية بإذن صاحبها، مع نسخة احتياطية، قبل تجربة محدودة ثم تعميمه. Native لديه مسار نسخة احتياطية قبل الترحيل؛ ترقية Web ذرية لكن لا تُعد نسخة احتياطية خارج المتصفح. الرجوع لإصدار قديم بعد رفع المخطط يتطلب استعادة نسخة ما قبل الترقية، لا خفض user_version يدويًا.

أُنجز أساس الأرصدة من 2ب في مخطط 10086: كمية وتكلفة لكل متغير ومخزن، وربط محرك تعديل الكمية بالمخزن الرئيسي، وتوافق ذري مع كتابات التكلفة والمخزون الحالية. هذا لا يكمّل فصل دفعات FIFO والتقارير ولا يفتح مخزنًا إضافيًا للتشغيل. التفاصيل في `WAREHOUSE_STOCK_VERIFICATION_AR.md`.

أُنجز بعده ربط خدمة الدفعات وقراءة WAC وتقارير الدفعات والتقييم بنطاق المخزن الرئيسي، مع معاملات مستقلة آمنة للاستهلاك والاستعادة وتعديل الصلاحية. لا تغيير للمخطط 10086. التفاصيل في `WAREHOUSE_BATCH_SCOPE_VERIFICATION_AR.md`. ما زال تشغيل مخزن إضافي يحتاج توجيه جميع المستندات ومسارات ترحيلها إلى مخزن محدد، ثم التحويلات والصلاحيات والاستحقاقات؛ هذا الربط لا يفعّله تلقائيًا.

أُضيف تحقق نطاق المستند وبنوده داخل 12 مسار ترحيل وإلغاء للفواتير والمرتجعات، مع تصفية تاريخ مرتجعات التسوية حسب المخزن والتحقق من نشاط الموقع قبل الجرد. اختبارات هذه الدفعة تشمل مصفوفة الأصناف والخصومات والمرتجعات المذكورة أعلاه. التفاصيل في `DOCUMENT_POSTING_SCOPE_VERIFICATION_AR.md`.

أُضيف ربط مباشر لأرصدة وتقارير الكمية والتكلفة بالمخزن الرئيسي: تقييم المخزون والحد الأدنى، مدخلات توزيع مخزون الموردين، والتقييم المحاسبي WAC والمسار الاحتياطي لـ FIFO. أُضيفت مراقبة أرصدة المخازن للتحديث الحي مع إبقاء الموقع المعطل ظاهرًا في التقييم. التفاصيل والحدود في `WAREHOUSE_REPORT_SCOPE_VERIFICATION_AR.md`. ما زال عزل تاريخ كل التقارير ومسارات الكتابة والتحويلات مطلوبًا قبل تشغيل مخزن إضافي.
