# تحقق سلامة فحص قاعدة البيانات — S1-07

تاريخ: 21 سبتمبر 2026. المحطة الأولى، إنجاز جزئي للبند S1-07.

## الخلل والإصلاح

كان فحص أدوات الإدارة ينشئ صنفًا ومتغيرًا برصيد ثم يحذفهما بخطوات منفصلة. فشل الإدراج أو التنظيف قد يترك بيانات تشخيصية أو آثارًا للمخزون.

نُقل الفحص إلى `DatabaseHealthCheckService.checkNullableVariantSku` داخل معاملة تتراجع عند النجاح والفشل. يُنشأ المتغير بكمية صفرية، وتتحقق قراءة SKU الفارغ والكمية، ثم تُلغى المعاملة بإشارة داخلية خاصة. الأعطال الفعلية تصل إلى الواجهة. أضيفت رسائل بالعربية والإنجليزية والفرنسية وفحص `mounted` قبل تحديث الواجهة بعد الانتظار.

هذا اختبار محدود لقبول SKU الفارغ وإدراج الصنف والمتغير، وليس تدقيقًا شاملًا لصحة الحسابات أو قاعدة البيانات.

## الاختبارات

`test/features/business/database_health_check_test.dart` يتضمن خمسة اختبارات:

- النجاح مع مقارنة جميع الجداول، بما فيها جداول المخازن و`sqlite_sequence`، قبل الفحص وبعده.
- تكرار الفحص ثلاث مرات دون أثر دائم.
- فشل إدراج المتغير بمحفز قاعدة بيانات مع التراجع عن الصنف وآثار المحفزات.
- فشل شرط SKU مع التراجع الكامل.
- فحص داخل معاملة قائمة دون إلغاء عمل المستدعي عند تراجع الفحص الداخلي.
