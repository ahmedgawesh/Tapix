# تحقق إعدادات المخزون وتصنيف الكتابات — S1-07

تاريخ المراجعة: 21 سبتمبر 2026. المحطة الأولى ما زالت قيد التنفيذ.

## الإصلاح

اعتمدت وظائف تغيير وحدة القياس وطريقة التكلفة ونوع التتبع في `ProductDao` على `assert`، الذي لا يعمل في نسخة الإصدار. إنشاء الصنف في `ProductRepositoryImpl` اعتمد عليه لنوع التتبع، ولم يتحقق من القيم المسموح بها لوحدة القياس وطريقة التكلفة.

أصبحت هذه المسارات ترفض القيم غير المعروفة بـ`ArgumentError` قبل أي كتابة. عند الإنشاء يحدث التحقق أيضًا قبل الوصول إلى حصة الأصناف أو تسجيل التدقيق. تبقى القيم المقبولة كما في عقد التعديل السابق:

| الإعداد | القيم |
| --- | --- |
| وحدة القياس | `piece`, `length`, `weight`, `volume` |
| طريقة تكلفة الصنف | `wac`, `fifo` |
| تتبع المخزون | `standard`, `batch`, `batch_expiry` |

لا تُعدَّل أصناف العملاء الحالية تلقائيًا. هذه حماية للمدخلات الجديدة. قفل الإعدادات عند وجود مخزون أو تاريخ حركة ما زال قائمًا؛ أُضيف تحقق صريح من قفل تتبع الدفعات عند وجود مخزون بعيد.

## أدلة الاختبار

- `inventory_policy_validation_test.dart`: 12 اختبارًا؛ رفض النص الفارغ والقيمة المجهولة واختلاف حالة الأحرف والمسافة الزائدة مع مقارنة البيانات قبل وبعد، وقبول جميع القيم التسع المسموح بها على صنف بلا حركة، وحفظ توافق نوع التتبع مع طريقة التكلفة.
- `warehouse_product_creation_atomicity_test.dart`: 3 اختبارات إضافية لرفض الإعدادات عند الإنشاء دون تغيير البيانات أو استهلاك حصة الترخيص.
- `warehouse_variant_management_test.dart`: توسيع اختبار القفل برصيد مخزن آخر ليشمل نوع تتبع الدفعات.
- الاختبارات تتوقع `ArgumentError` تحديدًا، فلا تمر اعتمادًا على `AssertionError` في وضع التطوير.

## تصنيف الكتابات التي تمت مراجعتها

| المسار | التصنيف والقرار |
| --- | --- |
| `StockService` | كاتب تشغيلي مركزي للكمية، مع نطاق المخزن والتحقق من هوية المتغير ومعاملة مرآة الصنف البسيط. |
| `ProductCostService` | كاتب تشغيلي مركزي للتكلفة وتجميع الأب؛ مرتبط بتحقق المخزن السابق. |
| `PurchaseDao` | الكتابات المباشرة المتبقية تخص الأسعار السابقة وسعر المورد وأسعار البيع والضريبة؛ كمية المخزون وتكلفته تمران بالخدمات. |
| `ProductDao.updateProduct` و`ProductVariantDao.updateVariant` | تعديل بيانات الصنف يستثني الرصيد والتكلفة والحقول التاريخية؛ إعدادات المخزون لها وظائف مخصصة. |
| إنشاء الأصناف والمتغيرات | تتبع المستدعين في `lib` يربط الواجهات والاستيراد بالمستودعات؛ إنشاء الصنف صفري، وإنشاء المتغير صفري يتبعه تسجيل الافتتاحي عبر الخدمة داخل المعاملة. |
| دوال إنشاء DAO | واجهات منخفضة المستوى؛ ليست حدود ترخيص أو محاسبة، ويجب ألا تُستخدم من واجهة أو مسار شبكة جديد لتسجيل افتتاحي مباشر. `ProductDao.createVariant` ليس له مستدعٍ تشغيلي ظاهر في البحث الحالي. |
| محولات نماذج المنتجات `toCompanion` | تمثيل بيانات؛ لم يظهر استدعاء تشغيلي لتحويلي الصنف والمتغير داخل ميزة المنتجات. تحديث صفوف Drift يستثني الحقول المالية كما سبق. |
| `business_warehouse_stock.dart` | ترقية ومشغلات توافق ذرية بين الرصيد القديم والمخزن الرئيسي؛ استثناء مقصود حتى اكتمال التشغيل بالمواقع، ولا يفتح تشغيل المخزن الثانوي. |
| `app_database.dart` | إعادة بناء SKU القديمة، إزالة تكرار المعرفات النصية، إصلاح بيانات الصنف البسيط، وترحيل تاريخ الأسعار والتتبع والضرائب: مسارات تهيئة/ترقية وليست فتحًا لكتابة تشغيلية عامة. |
| فحص الصحة | معاملة تشخيصية تتراجع دائمًا؛ موثق في `DATABASE_HEALTH_CHECK_VERIFICATION_AR.md`. |

## المتبقي

S1-07 لا يزال مفتوحًا لمراجعة أمان فشل إصلاح مخطط SKU القديم قبل تأسيس المخازن: توجد إعادة بناء قديمة للجدول مع تعطيل المفاتيح الأجنبية والتقاط الخطأ؛ يلزم التحقق من التعافي وفشل منتصف العملية على نسخة اختبار قديمة قبل إغلاق تدقيق الترقيات. وجود تصنيف «ترقية» لا يثبت وحده سلامة هذا المسار عند الفشل.

S1-06 ما زال مفتوحًا للعمولات والتصدير وLAN. لم يتغير مخطط قاعدة البيانات بهذه الدفعة، ولم تُعدَّل قاعدة الهاتف. بناء Linux وAndroid عند نهاية المحطة فقط.
